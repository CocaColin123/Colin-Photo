# 日记库 — 设计规格

## 概述

一个本地 Electron 桌面应用，用于电子化手写日记。用户通过千问 OCR 提取文字后粘贴到录入窗口，AI 自动解析日期/地点/标题并填入小框，确认后异步归档为 Markdown 文件。支持多排版预设、多页日记、图片嵌入/浮动/堆叠翻动。阅读和编辑提供 A4 纸面体验。

## 应用架构

- **Electron** 桌面壳
- **主进程**：文件系统读写、DeepSeek API 调用、窗口管理
- **渲染进程**：React 19 + Tailwind 4 + Motion

```
日记库/                          ← 用户首次启动选择一个本地文件夹
├── diary.config.json             ← 排版预设 + 全局偏好
├── 2026/
│   ├── 05/
│   │   ├── 2026-05-15-星期三.md
│   │   ├── 2026-05-27-海边.md
│   │   └── images/
│   │       ├── 2026-05-15/
│   │       └── 2026-05-27/
```

## Markdown 数据格式

```md
---
date: 2026-05-15
title: 星期三
location: 上海罗森
tags: [日常, 实习]
preset: my-style
---

正文段落一。

正文段落二。

![下午的光](images/2026-05-15/photo-01.webp){x:120,y:340,w:200}
![换个角度](images/2026-05-15/photo-02.webp){x:120,y:340,w:200}
```

- `date`：日期（YYYY-MM-DD）
- `title`：AI 生成或手动输入
- `location`：AI 从正文提取，可为空
- `tags`：AI 生成的标签数组
- `preset`：使用的排版预设名称，为空则用全局默认
- 连续 `![]()` → 堆叠翻动组
- `{x,y,w}`：浮动模式图片的坐标和宽度

## 五个视图 + 侧栏设置

侧栏底部两个固定入口：**API 设置**（齿轮图标）、**AI 助手**（聊天气泡图标）。

### 1. 欢迎页

应用启动后的首页。
- 大幅标题 + 档案库统计（已有 N 篇日记，跨度 X 年）
- 最近日记预览（3-5 篇卡片）
- 「进入档案库」→ 时间线
- 「录入日记」→ 录入窗口

### 2. 时间线

按年月分组的日记卡片列表。
- 左侧：年份/月份折叠导航
- 右侧：卡片网格，每张显示日期、标题、首段、标签
- 顶部：全文搜索
- 点击卡片 → 阅读模式
- 底部始终可见「录入日记」入口

### 3. 阅读模式

A4 纸面渲染当前日记。
- 排版按该日记指定的 preset（或全局默认）渲染
- 图片堆叠组：点击进入翻动模式（左右箭头）
- 右上角「编辑」→ 切换到编辑模式

### 4. 编辑模式

所见即所得编辑器。
- 文字区域：contenteditable
- 右侧面板：排版参数 + 预设管理
- 图片拖动、浮动定位
- 「保存」写回 .md

## 排版预设

### 参数（全部开放无上限）

**纸张**：宽高比、页边距（上下左右独立）、页阴影强度

**文字**：字体、字号、行高、字间距、段间距、颜色、首行缩进

**背景**：底色、纹理图（横线/方格/点阵/自定义）、纹理透明度

**图片**：默认模式（嵌入/浮动）、环绕间距

### 预设管理

- 存储于 `diary.config.json` 的 `presets` 数组
- 全局默认预设（`default`，不可删除）
- 用户可新建、重命名、删除自定义预设
- 编辑模式下调好参数 → 「保存为预设...」
- 录入模式下可选择预设（下拉或卡片）
- 每篇日记的 `preset` frontmatter 记录使用哪个预设

### 布局

```
┌──────────────────────────────────────────┐
│  日记录入                    [选择预设 ▾] │
├──────────────────────────────────────────┤

│   │                                  │   │
│   │  大粘贴框                        │   │
```

### 流程

```
用户粘贴千问 OCR 输出到大框
  ↓
正则解析：
  1. 跳过千问开场白（"根据您提供的图片..."）
  2. 提取日期（YYYY.M.DD → YYYY-MM-DD）
  3. 提取正文（去除日期行和地点行）
  ↓
AI 填充小框（异步，粘贴后 1-2 秒内完成）：
  - 日期自动填入，可手动改
  - 地点从正文提取，可手动改
  - 标题由 DeepSeek 生成，可手动改
  - 标签由 DeepSeek 生成，可增删
  - 正文中已提取到小框的内容（日期行、地点行）自动从大框中去除或淡化
  ↓
用户检查小框 → 无误 → 点击「确认归档」
  ↓
录入窗口立即清空，大框恢复绿色脉冲等待下一次粘贴  ← 非阻塞
  ↓
后台异步：
  1. 生成 Markdown 文件
  2. 写入磁盘
  3. DeepSeek 审核：检查正文质量（OCR 错字、不通顺处）
     - 有问题 → 在时间线中该日记上标注 ⚠️ 图标，点击查看问题列表
     - 没问题 → 不标注，静默完成
```

### 多页日记

勾选「多页日记」→ 指定页数 N → 粘贴 N 篇 OCR 文本（用分隔符或分别粘贴 N 次）→ 归档时生成 N 个 .md 文件，文件名加页码后缀 `2026-05-15-星期三-page1.md`、`page2.md`...

相同日期 + 相同标题 + 连续页码 = 阅读时显示「第 1 页 / 共 N 页」，可翻页。

### 异常处理

- **检测不到 📅**：日期小框闪红，等待手动填写
- **正文为空**：提示"未检测到有效内容"，保留粘贴内容
- **粘贴了多篇**：识别后弹出"N 篇日记待确认"，切分为独立确认组，可逐篇或批量确认
- **文件已存在**：提示"该日期已有日记"，选项：覆盖 / 合并为多页 / 取消
- **DeepSeek API 故障**：跳过 AI 增强，正则提取日期 + 取正文前 15 字为标题，不阻塞录入

## DeepSeek API 使用

### 第一次调用（录入时）

- 触发：粘贴后自动
- 输入：清洗后的正文文本
- 输出：`{ title, location, tags }`
- 失败：不阻塞，手动填写

### 第二次调用（归档后审核）

- 触发：确认归档后异步执行
- 输入：完整日记正文
- 输出：`{ issues: [{ original, suggested, severity }] | null }`
- 无问题返回 null → 不标注
- 有问题 → 存入该日记的 frontmatter 或 sidecar JSON，时间线卡片标 ⚠️

### 成本

deepseek-chat 约 ¥1/百万 token。单篇日记 ~1000 token，1000 篇约 ¥1。

## 图片管理

- 图片存放在对应日记的 `images/日期/` 子目录
- 支持 jpg、png、webp
- 编辑器内拖入图片文件 → 复制到目录 → 插入 `![]()`
- 浮动模式位置存为 `{x,y,w}`
- 连续多张 `![]()` = 堆叠翻动组

## API 设置面板

侧栏底部齿轮入口，独立小面板（非全屏页面）。

### 功能

- **API Key**：输入框，密码遮蔽，存储在本地配置文件（不提交 Git）
- **提供商选择**：下拉（DeepSeek / OpenAI 兼容 / 自定义 endpoint）
- **模型选择**：下拉或自由输入模型名（默认 `deepseek-chat`）
- **Base URL**：可编辑（默认 `https://api.deepseek.com`）
- **连接测试**：按钮 → 发送一条简短请求 → 显示 ✅ 或 ❌ + 错误信息
- 配置持久化到 `diary.config.json` 的 `api` 字段

### 存储格式

```json
{
  "api": {
    "provider": "deepseek",
    "baseUrl": "https://api.deepseek.com",
    "apiKey": "sk-xxx",
    "model": "deepseek-chat"
  }
}
```

## AI 助手（本地文件管家）

侧栏底部聊天气泡入口，独立对话面板。

### 定位

工作区 = 日记库根目录。AI 可以读取文件列表、日记内容、项目进度，但不能修改文件。

### 能力

- **项目概览**："我现在有多少篇日记？" → 回答总数、时间跨度、最近更新
- **进度查询**："这个月写了几篇？" → 统计当月
- **内容搜索**："提到糕糕的日记有哪些？" → 全文检索 + AI 总结
- **标签分析**："过去三个月最常出现的标签" → 统计
- **排版建议**："我的日记排版有什么可以改进的？" → 分析当前 preset

### 实现

- 系统 prompt 告知 AI 日记库目录结构、Markdown 格式
- 每次对话时，前端自动收集上下文注入（日记总数、日期范围、标签列表等元数据）
- 用户提问涉及具体内容时 → Electron 主进程读取对应文件 → 注入上下文
- 使用用户配置的 API Key 和模型
- 对话历史存在 `diary.config.json` 的 `chatHistory` 字段（最近 50 条）

### 不做的

- 不修改文件（只读）
- 不执行命令
- 不上传文件到第三方（只调 API）

## 不涉及

- 密码/登录
- 云同步
- 多用户
- OCR 本身（由千问完成）
- 手机端
